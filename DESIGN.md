# Piñata — DESIGN.md

**Chosen 2026-10-27:** "Paper Fiesta", from Stitch round 2 (project `4918037056990527388`, design system
`assets/16701628938964931394`). It replaces V7 Neon Pastel (round 1, project `1263055774257026422`), which is
retired. Tokens and component styles live in [public/pinata.css](public/pinata.css); the Tailwind names that map
onto them are in [src/app/globals.css](src/app/globals.css). This file is the taste document and the rulebook:
**an agent changing anything visible reads the Rules section first.**

## Brand

- **Name: Piñata.** The pooled money is the piñata: it stays shut, nobody sees inside, and it gets smashed
  open at the event. Owner-blindness in a party costume.
- **Spelling:** humans read **Piñata**; every URL, package name, env var, slug, domain and filename uses
  `pinata`. The ñ never appears in an identifier.
- **Tagline:** group gifts nobody can spoil.
- **Mark:** the donkey piñata tile on its navy rounded square, shipped as [src/app/icon.png](src/app/icon.png)
  (512) and [src/app/apple-icon.png](src/app/apple-icon.png) (180). Generated by the owner (Gemini, 2026-10-26),
  so no third-party rights question; the source JPG stays out of the repo. The tile navy is the mark's own ground,
  not a UI colour. In the header the tile gets the 2px offset shadow like any other sticker.
- **Wordmark:** live type — Bricolage Grotesque 800, -0.02em — never traced paths, so the ñ renders correctly.
- **No cursive or script lettering anywhere**, including the wordmark. **No italics.**

## The idea

A cut-paper party on cream stock. White cards with an ink outline and a hard offset shadow, like stickers
on a paper tablecloth; a tissue-paper fringe under the header in the five piñata colours. Warm and tactile,
grown-up rather than childish — the first screen most people see is a join link opened inside WhatsApp's
in-app browser, and it has to feel like a friend's party, not a fintech form.

| `money` | #2E7D6B | settled stamp fill, completed meter; `money-ink` #246B5B for amounts and eyebrows |
| `lilac` / `sky` | #B9A6F2 / #8FD3F4 | decoration: fringe, avatars |

**Washes carry meaning, not decoration:** lilac = a person or a secret, green = money, marigold = still open,
tomato wash = needs attention. A new surface picks its wash by what it is about, never to alternate colours.

## Typography

- **Bricolage Grotesque 800** — h1 (fluid 34–52px), section heads 22px, list titles 20px, the big money
  figures, the wordmark. Sentence case, -0.02em.
- **DM Sans 400** body 15/23 (16 from tablet); **600** labels and names; **700** buttons, badges, eyebrows.
- Eyebrows: DM Sans 700, 12px, uppercase, 0.1em tracking, `money-ink`.
- Tabular figures on every amount.
- Fonts are self-hosted from `public/fonts/` (OFL, licences beside the files) and precached by
  [public/sw.js](public/sw.js). Changing a font file means changing `SHELL_URLS` and bumping `VERSION` there.

## Shape and depth

- `--pn-line`: 1.5px solid ink on every card, button, badge, input-like control.
- `--pn-lift`: `3px 3px 0 ink` — hard, no blur — on top-level cards and buttons; `--pn-lift-sm` (2px) on
  chips, stickers, CTAs. **A card nested inside a card has no shadow** (outline only).
- Pressing a button moves it `translate(2px, 2px)` into its shadow.
- Radii: 18px panels, 14px cards, 12px buttons/inputs, full pills for badges and chips, circles for avatars.
- Notes and empty states use a dashed 1.5px border on paper tint instead of a shadow.
- The fringe under the header is the one ornament. Do not add others (no confetti, no gradients, no glow).

## Components

- **Buttons:** primary = tomato fill, white DM Sans 700, 48px tall, ink outline + lift. One primary per
  screen. Secondary = white fill, ink text. Quiet = link-coloured text, no outline. Disabled = paper fill,
  `ink-2` text, no shadow.
- **Header:** paper, brand tile + wordmark, a **sticker** naming the side (`Friends only` with a lock on
  lilac, `Owner view` on marigold, rotated -2°), the circle name, then the fringe.
- **Tab bar (mobile):** white, ink top rule; the current tab is a marigold pill with an ink outline.
- **Item card:** white sticker card; title is the link (Bricolage, marigold underline); price in `money-ink`;
  one status badge; the pool sits in a nested green block with the meter and "R… settled of R…".
- **Meter:** paper track with ink outline, marigold candy-stripe fill; full or done turns green.
- **Badges:** `<Badge tone>` takes a meaning — `human`, `money`, `done` (solid green stamp with ✓), `open`,
  `alert` (with !), `neutral`. Never pass a colour name.
- **Amount fields:** `<AmountField>` — the R sits inside the input, `inputMode="decimal"`, the server parses
  with `parseRandToMinor`. Quick picks are separate submit buttons (`.pn-picks`), so a pledge needs no JS.
- **Card messages:** white quote on the lilac card, 3px tomato left rule, DM Sans 600, no italics.

## Rules (agents: these are the checks a change must pass)

1. **Numbers never break.** An amount or a date is one token on one line. `formatMinor()` joins digit groups
   with U+00A0 and every rendered amount sits in `.pn-money`, `.pn-price`, `.pn-summary-figure`,
   `.pn-stat > dd` or `<Money>` — all `white-space: nowrap`. Never build an amount with a plain space, never
   put `overflow-wrap: anywhere` or `word-break: break-all` on text that can contain one. Dates go through
   `<EventDate>`. Proven by `tests/lib/money.test.ts` and the friend-ledger "never lets an amount wrap" test.
2. **Nobody types cents.** Every money input is rand via `<AmountField>`; the route converts. Copy never says
   "cents", "minor units" or "ZAR" to a person.
3. **Plain words, no engine states.** People never read `tombstoned`, `pivot_needed`, `active`, `status:`.
   The friend wording lives in one place, [src/components/status.ts](src/components/status.ts) — extend it
   there, never inline. Current vocabulary: *No pool yet · Pooling · R… to go · Fully pooled · Bought ·
   Needs a new plan · Pool paused · You're buying it · They bought it themselves · Off their list · Revealed.*
4. **Never claim what the projection cannot see.** A friend's view has no other friends' claims, so a row
   says "No pool yet", never "Up for grabs" or "Unclaimed". The list shows settled against target only —
   no head counts, no "pledged" money (the item page may show "N contributions recorded").
5. **Wash = meaning** (table above). Tone names in code are meanings (`human`, `money`, `open`, `alert`,
   `done`), not colours.
6. **Contrast:** text pairs ≥ 4.5:1. Marigold, tomato (#E4572E), lilac and sky are never text colours.
7. **One stylesheet.** Styles go in `public/pinata.css` (shared by Next and the raw `/c/<slug>` HTML). Inline
   `style` only for a runtime value (the meter's `--pn-fill`). New tokens get a Tailwind mapping in
   `src/app/globals.css`.
8. **Phone first:** check 360px wide with no horizontal scroll; 44px minimum touch targets.
9. **Card PNG** ([src/server/cards/render.ts](src/server/cards/render.ts)) uses the same palette hexes; change
   both together. Its font stays the bundled Geist TTF (satori needs a TTF).

## Product rules the UI must obey

- Owner view ≠ friend view: any new component declares which projection renders it.
- Deal suggestions reach friends only; the owner must not learn a cheaper option exists.
- The reveal is a human act: card routes get `robots: noindex` and no `og:` preview — the circle link lives
  in a WhatsApp group that contains the owner.
- The assistant never decides what happens next: fixed menu copy only, no free-form chat UI and **no "Chat"
  tab** (Stitch mocks invent one; drop it).
